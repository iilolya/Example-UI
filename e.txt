Gradle представляет набор инструментов для автоматической сборки, который позволяет настраивать и управлять сборкой проектов с помощью специальных файлов конфигурации.  Gradle — это зависимости - модули, которые необходимы для работы приложения и функционаьность которых используется в приложении.

Проект приложения может состоять из одного или нескольких модулей. И для каждого модуля потребуется собственный файл сборки Gradle. МОДИФИКАТОР
 modifier - модификатор, который устанавливает различные аспекты внешнего вида и поведения компонента. Применяется ко многим компонентам.
Для установки размеров компонентов в Jetpack Compose определен целый ряд модификаторов: (Для установки применяются единицы dp)
•	Modifier.height(): устанавливает высоту
•	Modifier.width(): устанавливает ширину
•	Modifier.fillMaxHeight(): растягивает компонент по всей длине контейнера
•	Modifier.fillMaxWidth(): растягивает компонент по всей ширине контейнера
•	Modifier.fillMaxSize(): растягивает компонент по всей длине и ширине контейнера
•	Modifier.heightIn(): устанавливает минимальную и максимальную высоту
•	Modifier.widthIn(): устанавливает минимальную и максимальную ширину
•	Modifier.size(): устанавливает размер
•	Modifier.sizeIn(): устанавливает минимальный и максимальный размер
•	heightIn() и widthIn() принимают два значения - минимальные и максимальные значения
•	отступов внутри компонента применяется модификатор padding()
•	Для сдвига содержимого компонента по горизонтали и вертикали применяется модификатор offset
•	Для добавления прокрутки содержимого по горизонтали применяется модификатор Modifier.horizontalScroll
o	Параметры модификатора:
	state: представляет объект ScrollState и описывает состояние полосы прокрутки
	enabled: значение типа Boolean, которое указывает, будет ли прокрутка доступна. По умолчанию имеет значение true
	flingBehavior: представляет объект FlingBehavior и описывает поведение при завершении прокрутки. По умолчанию имеет значение ScrollableDefaults.flingBehavior
	reverseScrolling: устанавливает направление. При значении true прокрутка идет в обратном направлении. По умолчанию имеет значение false
•	rememberScrollState мы можем сами определять состояние полосы покрутки
•	Для добавления прокрутки содержимого по вертикали применяется модификатор Modifier.verticalScroll:
•	Модификатор border позволяет определить границу вокруг компонента.

•	Измененяемое состояние в Jetpack Compose представлено объектом интерфейса MutableState<T>, Для создания объекта MutableState<T> Jetpack Compose предоставляет функцию mutableStateOf(): В функцию mutableStateOf() в качестве параметра передается отслеживаемое значение. Возвращаемый из функции объект MutableState позволяет связать отслеживаемое значение с компонентом. (переобновление данных)

ViewModel
Её задача — быть «умной прослойкой» между данными и интерфейсом. Она работает с данными, но не напрямую. ViewModel — это класс, предназначенный для хранения и управления данными, связанными с пользовательским интерфейсом, с учётом жизненного цикла. Его основная задача - пережить изменения конфигурации.
Что ViewModel делает на самом деле
1.	Переживает пересоздание экрана — хранит состояние, пока Activity/Fragment уничтожается при повороте или смене темы.
2.	Готовит данные для UI — запрашивает их у слоя данных, фильтрует, трансформирует, упаковывает в удобный формат (StateFlow/LiveData).
3.	Управляет UI-логикой — что показать при загрузке/ошибке, как обработать клик, какие события отправить вниз по потоку.
Основная цель ViewModel — обеспечить работу с данными с помощью пользовательского интерфейса.

Да, описанный в лабораторной работе подход является устаревшим для внутренней навигации внутри современного Android-приложения.

Логика старого подхода (по шагам, как в лабе):
1 Концепция: 1 экран = 1 Activity
2 Запуск экрана через Intent
val intent = Intent(LocalContext.current, AboutMeActivity::class.java)
LocalContext.current.startActivity(intent)
3 Передача данных: putExtra()
 
•	Данные упаковываются в Bundle (пары ключ/значение).
•	Bundle сериализуется через системный Binder и передаётся в новый процесс/окно Activity.
•	Поддерживаются только примитивы, String, Serializable, Parcelable, массивы.
4  Получение данных в целевом Activity
 
5 кнопка назад Системная кнопка "Назад" вызывает finish() для текущей Activity и возвращает пользователя на предыдущую.
Ключевым объектом для создания визуального интерфейса в приложении Android является класс Activity, а Composable-функции фактически размещаются внутри Activity. Activity — это окно-контейнер приложения. В нём живёт один главный экран, а все остальные меняются внутри него. Все "экраны" — это @Composable функции или
6  Поворот экрана / смена темы
•	Система уничтожает и пересоздаёт Activity.
•	Intent с данными сохраняется автоматически.
•	Проблема: состояние UI (введённый текст, позиция скролла, ошибки валидации) теряется, если не использовать onSaveInstanceState() или ViewModel. В лабе это не учитывается.
Intent — это объект-сообщение, который используется для:
1. Открыть другое приложение (браузер, карты, камера)
2. Поделиться/Отправить данные (текст, фото, файл)
3. Получить результат из системы (выбрать фото из галереи, сделать фото)

•	Передачи данных между ними
•	Вызова действий других приложений (открыть ссылку, сделать фото, позвонить)

Что это: UI-контейнер, в котором отрисовывается текущий экран. NavHost не управляет переходами. Он только отображает то, что ему скажет NavController.
NavController (Контроллер навигации)
Что это: Объект-«мозг» навигации. Управляет историей экранов (back stack), вызывает переходы, обрабатывает системную кнопку «Назад».
NavArgs (Аргументы навигации)
Что это: Типобезопасный способ передать данные между экранами. Заменяет Intent.putExtra() и ручное парсинг Bundle.
